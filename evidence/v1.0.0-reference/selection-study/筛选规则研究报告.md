# 收益筛选规则：结构分析与目标机器校准

## 结论的依据

旧四项结构阈值只适合作为候选范围。四边形网格反例的尾部占比约3.9%，低于三角形网格约5.4%；估算循环指令减少约14.4%，高于三角形网格约13.7%，却出现回退。bcsstk16和反例的行长中位数同为54。因此不能把回退简单归因于尾部太多、减少指令太少或中位行长54。

features.json还保存了行长熵、相同行长占比、相邻同行长比例、矩阵字节数以及假设64字节缓存行下的向量访问特征。这些是静态描述与分析估算，不是硬件性能计数器。没有新的PMU证据，不能宣称已证明分支预测或缓存是原因。

本轮不追加按矩阵名、领域或测得结果反推的结构阈值。改为先过结构/机器码安全条件，再进行目标机器上的保守实测校准。

## 固定的选择规则

1. 机器码必须通过既有变换识别与安全检查；正确性不依赖收益阈值。
2. 四项结构条件保持不变，仅限定候选范围。
3. 在目标机器以同一O3输入、相同常规BOLT配置比较pgo和new。两批各12轮随机配对；两批收益点估计都至少2%，且各自95%配对bootstrap区间下界都大于1%，才启用。
4. 不满足、结果不确定或校验失败时，保留常规BOLT；不能把失败结果从报告中删除。
5. 选择绑定矩阵SHA256、二进制SHA256和环境记录。换数据、换CPU或重要运行环境变化后重新校准。JSON中的绑定是审计信息，不是运行时强制检测。

2%与1%是预先确定的工程裕量，不是最优阈值或统计保证。12轮bootstrap也不能排除系统性噪声。该流程适合长期重复计算同一类/已知数据的部署，不适合每个矩阵仅执行一次。

## 交付建议

两台机器各12份选择profile均实际传入冻结llvm-bolt生成程序，并检查可执行节地址与字节：启用者与new一致，跳过者与pgo一致。记录见各主机profile-checks.json。

保留冻结变换作为优化核心；新增规则定位为可选部署校准工具，不宣称是新的通用优化算法。若提交材料需要无校准成本的自动收益选择，当前工作尚未解决。若要求某一份部署配置在两台已测机器均有收益，可要求它分别通过两机校准；这仍不能推及所有机器。

不建议继续把已有反例排除后重新宣称结构规则可靠。后续最有价值的验证是先冻结完整校准流程，再拿未见矩阵进行端到端验证，且计入校准成本。

本次实测校准成本对应的摊销次数很高，说明该方案更适合安装/离线验证一次后反复复用结果，而非每次执行或每个一次性矩阵都校准。没有实际足够的重复调用时，不应以计算阶段收益声称整体更快。
